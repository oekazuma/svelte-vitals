Source analysis now follows a component a route renders when it is imported through a barrel module (`export { default as SeoHead } from './SeoHead.svelte'` in an `index.ts`, `export *`, nested barrels, `export default` of an imported component), through a namespace import (`import * as Page from '$lib/page'` then `<Page.Title>`), or through a local holding it (`const C = $derived(cond ? A : B)`, `{@const C = …}`, `<svelte:component this={X}>`). Such a component's `<title>`, meta tags, JSON-LD and `<h1>` were invisible, so routes that set them this way were reported as missing them — including critical `seo/title-presence` findings. When a local may hold one of several components, their head tags count as dynamic and an `<h1>` in any of them keeps `seo/single-h1` from reporting the route as missing one. What those components render now also counts toward the other head and heading rules, so a shared literal description can surface `seo/duplicate-description` and a component's `<h1>` next to the page's can surface a `seo/single-h1` "Multiple <h1>" finding. The a11y composition follows the same components, so fewer routes are skipped by `a11y/no-missing-id-ref` and newly visible ids, landmarks and elements can surface findings from those components.
