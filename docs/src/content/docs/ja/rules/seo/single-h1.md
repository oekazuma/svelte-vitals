**重大度:** warning（`<h1>` なし）/ info（`<h1>` が複数）

## チェック内容

`<h1>` が 0 個（主見出しなし、`warning`）、または 2 個以上（`info`）のページを検出します。ちょうど 1 個で合格です。ページのレイアウトチェーンにある見出しもそのルートの集計に含めるため、`+layout.svelte` の `<h1>` もカウントされます。

[グローバルな重大度上書き](/ja/guides/configuration)（`rules: { 'seo/single-h1': <severity> }`）は両方のケースに一律で適用されます。設定はルール ID 単位のキーであり、どちらのケースで検出されたかは区別しないため、上書きすると分割は 1 つの重大度に均されます。

## なぜ重要か

`<h1>` はページの主トピックを表す見出しです。`<h1>` が 0 個だとページに主見出しがなくなります。シグナルが本当に欠けている状態なので `warning` です。一方、単一の明確な `<h1>` はページのトピックを示す慣例的なシグナルですが、複数の `<h1>` は現代の見出しアルゴリズムでも許容されています。複数あることでランキングにペナルティが科されるという公式情報源はないため、こちらはスタイル上の指摘（`info`）にとどめ、欠陥としては扱いません。

## 修正方法

```svelte +page.svelte
<h1>ページ唯一の、内容を表す説明的なメインの見出し</h1>

<h2>サブセクション</h2>
<h2>別のサブセクション</h2>
```

## モードによる違い

両モードとも見出しを収集しますが、収集元が異なるため結果が食い違うことがあります。

- **ソース解析**（CLI、ダッシュボードの静的ベースライン）はルートの `.svelte` テンプレートを走査します。インポートしたローカルコンポーネントが描画する見出しも（head 解決と同じ、深さ制限付きの走査で再帰的に）追跡するため、`<h1>` を `$lib` コンポーネントに切り出しても検出されます。barrel の `index.ts` 経由で再エクスポートされたコンポーネント、名前空間のメンバー（`<Ui.Title>`）、インポートしたコンポーネントを保持する `const`/`$derived`/`{@const}` も追跡します。複数の候補のどれかを保持する場合、そのいずれかに `<h1>` があれば、そのルートを「`<h1>` が見つかりません」とは報告しません。1 つの `{#if}`/`{:else if}`/`{:else}` や `{#await}` ブロックの各分岐は同時に描画されません。`<svelte:boundary>` の中身と `failed`/`pending` スニペットも同様です。そのため、`<h1>` が最も多い分岐だけを数えます。分岐には、その中に置いたコンポーネントも含みます。ページは、レイアウトの `<slot />`/`{@render children()}` がある分岐の中で描画されるものとして扱います。別々のブロックは両方の条件が成り立ちうるので合算します。`{#if false}` のようなレンダリングされない分岐や、コンポーネントに渡されない prop に依存する分岐の中の見出しも数えてしまう一方、`node_modules` 由来のコンポーネントや、実行時にデータや対応表から選ばれるコンポーネントは見えません。そのため、解決できないコンポーネント内の見出しは依然として偽の「`<h1>` が見つかりません」を招くことがあります。また、別々の条件ブロックにある `<h1>` は、`info` レベルの過剰カウントを招くことがあります。
  `<svelte:element this={…}>` は、タグの式が文字列リテラルの場合、または両方の分岐がリテラルで見出しレベルが 1 つに定まる条件式（`this={featured ? 'h1' : 'span'}`）の場合、解決先の要素としてカウントします。``this={`h${level}`}``・変数・見出しレベルが 2 つに分かれる条件式のようにタグを特定できない場合は、その要素がページの `<h1>` である可能性があるため、「`<h1>` が見つかりません」と報告せず、そのルートを対象外にします。
  たどれないコンポーネント（`node_modules` のものなど）に、`tag`・`as`・`element`・`is` のいずれかに文字列リテラル `h1` を渡している場合（`<Heading tag="h1">`）も同じ扱いです。そのコンポーネントがページの `<h1>` を描画する可能性があるため、そのルートは報告しません。ほかの属性（`value="h1"`）やほかのレベル（`tag="h3"`）は `<h1>` の有無と関係がないため、対象外です。
- **レンダリング解析**（Vite プラグインのビルド、ダッシュボードで訪問したルート）はレンダリング済みの HTML を読みます。そのため、コンポーネントが描画したすべての見出しを認識し、実際にレンダリングされた分岐だけを数えます。

両者が食い違う場合は、レンダリング結果（`@svelte-vitals/vite`）を信頼してください。ブラウザに配信される内容を反映しているのはそちらです。

## 無効化

既存の検出は suppressions ファイルに記録して抑制できます（`npx svelte-vitals --update-suppressions`）。`overrides` でルートやパス単位に絞るか、ルールごと無効化するには、次のように設定します。

```js svelte-vitals.config.js
export default {
  rules: {
    'seo/single-h1': 'off'
  }
};
```
