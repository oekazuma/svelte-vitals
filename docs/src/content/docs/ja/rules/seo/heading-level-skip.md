**重大度:** info

## チェック内容

直前の見出しからレベルが2段以上跳ね上がる見出し（例: `<h2>` の直後に `<h4>`）を検出します。単一の `<h1>` の有無は `seo/single-h1` が担当します。

## なぜ重要か

見出しレベルを飛ばすとドキュメントアウトラインが崩れます。支援技術はこのアウトラインを頼りにページ構造を読み取っており、検索エンジンも構造シグナルの1つとして利用します。

## 修正方法

```svelte
<h1>ページタイトル</h1><h2>セクション</h2><h3>サブセクション</h3>
```

## モードによる違い

両モードとも見出しを収集しますが、収集元が異なるため結果が食い違うことがあります。

- **ソース解析**（CLI、ダッシュボードの静的ベースライン）はルートの `.svelte` テンプレートを走査します。そのため、`{#if false}` のようなレンダリングされない分岐の中にある見出しも数えます。見出しは文書順に読みます。ページはレイアウトが `<slot />`/`{@render children()}` を描画する位置に、スニペットの見出しは `{@render}` の位置に、インポートした子コンポーネントが描画する見出し（[seo/single-h1](/ja/rules/seo/single-h1) と同じくたどります）はそのコンポーネントのタグの位置に置きます。コンポーネントの見出しは、ルート自身のファイルの見出しの直前の見出しとしてだけ使います。また、その見出しが描画されるときに必ず描画される場合に限ります。閉じたダイアログやメニューの中の見出しや、独自の `{#if}` の中に置いたコンポーネントの見出しは、間を埋めません。コンポーネントの見出しでのレベル飛ばしは報告しません。レイアウトの共通部分の飛ばしが、各ページ自身の指摘の代わりになってしまうのを避けるためです。`{#each}` の本体は空になりうるものとして読みます。直前の見出しがブロックの 1 つの分岐にある場合は、分岐ごとに 1 つの描画として扱います。各分岐の最後の見出しと比べ、最も低いレベルを使います。例外は、その見出しが判定する見出しの外側の `{#each}` で繰り返される場合です。最後の回にどの分岐を通るかはデータ次第なので、直前の見出しだけを使います。ソースからレベルが決まらない `<svelte:element>`（`this={`h${level}`}` やタグを受け取る prop）は、レベルを持たないまま位置だけを占め、その直後の見出しは判定しません。1 つの `{#if}`/`{:else if}`/`{:else}` や `{#await}` ブロックの各分岐は別々に読みます。`<svelte:boundary>` の中身と `failed`/`pending` スニペットも同様です。ページは、レイアウトの `<slot />`/`{@render children()}` がある分岐の中にあるものとして読みます。1 つの `{#if}` の複数のアームで描画するレイアウトでは、ページをそれぞれのアームに置きます。別々のブロックに分かれている場合は、共通する位置に置きます。コンポーネントに渡した中身も、そのコンポーネントがそれを描画する分岐の中にあるものとして読みます。見出しは、同時に描画されうる直前の見出しと比べ、隣の分岐の見出しとは比べません。別々のブロックはすべて描画されるものとして扱います。ただし、同じ分岐にある `{:else}` のない `{#if}`（間に別のブロック・`{#each}`・コンポーネントを挟まないもの。要素は挟んでもかまいません）で、条件が 1 つの値について互いに矛盾するもの（`{#if pitch}` と `{#if !pitch}`）は、1 つのブロックの分岐として読みます。
- **レンダリング解析**（Vite プラグインのビルド、ダッシュボードで訪問したルート）はレンダリング済みの HTML を読みます。そのため、コンポーネントが描画した見出しも認識し、実際にレンダリングされた分岐だけを数えます。

両者が食い違う場合は、レンダリング結果を信頼してください。ブラウザに配信される内容を反映しているのはそちらです。

## 無効化

既存の検出は suppressions ファイルに記録して抑制できます（`npx svelte-vitals --update-suppressions`）。`overrides` でルートやパス単位に絞るか、ルールごと無効化するには、次のように設定します。

```js svelte-vitals.config.js
export default {
  rules: {
    'seo/heading-level-skip': 'off'
  }
};
```
