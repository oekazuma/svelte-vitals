# Docs homepage demo GIF Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a looping terminal-recording GIF of `svelte-vitals` running (the
pulse-line Health-score animation settling into a final score, followed by
the category score lines) to the Hero section of the docs homepage, in both
locales.

**Architecture:** A small hand-authored SvelteKit-shaped fixture at
`docs/demo/` gives `svelte-vitals` something realistic to analyze. A
`vhs` (Charm) `.tape` script records a real terminal session running the
built CLI against that fixture to `docs/public/demo.gif`. Both
`docs/src/content/docs/index.mdx` and its `ja/` counterpart reference that
one GIF via Starlight's native `hero.image.html` field.

**Tech Stack:** `vhs` (external Go binary, installed via Homebrew — not an
npm dependency, not added to any `package.json`), the already-built
`packages/cli` binary, Astro/Starlight (`docs` package, already in place).

## Global Constraints

- **Scope:** `docs` package only (plus the standalone `docs/demo/` fixture,
  which is not a pnpm workspace member). No changes to `packages/core` or
  `packages/cli` source.
- **No changeset:** this is a docs-only change (AGENTS.md: "Internal-only /
  doc-only changes don't need one").
- **en/ja stay in sync:** both `docs/src/content/docs/index.mdx` and
  `docs/src/content/docs/ja/index.mdx` must reference the same
  `docs/public/demo.gif` (no separate ja-specific recording — the terminal
  output is English regardless of locale).
- **Hard dependency on `feat/console-reporter-compact-animated` (PR #167)
  being merged to `main` before Tasks 3–4 execute.** The pulse-line score
  animation and `--reporter console`'s compact-by-default output do not
  exist on `main` yet. Task 1 (the fixture) and Task 2 (the tape script
  text) have no such dependency and may proceed immediately; do not run
  Task 3's actual `vhs` recording, or attempt Task 4's real embed
  verification, until `main` contains that merge — rebase/recreate this
  branch from `origin/main` first if it was branched before the merge
  landed (see this repo's Task 7 incident in
  `docs/superpowers/plans/2026-07-10-console-reporter-compact-animated.md`
  for what goes wrong if a worktree's branch point silently drifts).
- **No CI automation:** the GIF is a hand-curated asset, regenerated
  manually (`vhs docs/demo/demo.tape`, committed) when the animation or
  console output visually changes. No CI job verifies its freshness.
- **`vhs` is an external tool, not a project dependency:** install via
  `brew install vhs` on the machine doing the recording. Never add it to
  any `package.json` or `pnpm-workspace.yaml` catalog.

## File Structure

- `docs/demo/` — a small SvelteKit-shaped fixture (Task 1). Not a pnpm
  workspace member: `pnpm-workspace.yaml`'s `packages:` list is the literal
  string `'docs/'` (no wildcard), so a nested `docs/demo/package.json` is
  invisible to pnpm, exactly like the existing nested fixtures under
  `packages/cli/test/fixtures/*/package.json`.
- `docs/demo/demo.tape` — the vhs recording script (Task 2).
- `docs/public/demo.gif` — the recorded GIF, generated by running vhs
  against `demo.tape` (Task 3). Binary output, not authored as text.
- `docs/src/content/docs/index.mdx`, `docs/src/content/docs/ja/index.mdx` —
  gain a `hero.image.html` entry referencing `demo.gif` (Task 4).

- **Score too high (> 96):** add a second flaw to a category currently at
  100 — e.g. give `ContactCard.svelte` a 13th prop (`ARCH002` deducts more
  only if it crosses further category-average dilution, so prefer instead
  duplicating the `about` page's `javascript:` URL pattern onto one more

  image) — any category currently reads as `90`, `97`, or `100`; only `100`

  outside the design's intended shape.
- **Score too low (< 90) or a `critical` shows up:** first check
  `summary.critical` is `0` — if not, find which route lost its `<title>`
  and restore it (this is the one flaw class this fixture must never
  contain). If still too low with `critical: 0`, remove the `$effect` in
  `products/+page.svelte` (drops Correctness's second flaw) or the
  `javascript:` link in `about/+page.svelte` (drops Security's second flaw)
  — each removal raises its category from `90` back to `95`, moving the
  overall Health up roughly 1 point per category restored.

- [ ] **Step 1: Write the tape script**

`docs/demo/demo.tape`:

```text
Output ../public/demo.gif

Set Shell "bash"
Set FontSize 20
Set Width 1200
Set Height 630
Set Theme "Dracula"
Set Padding 20
Set TypingSpeed 60ms
Set Framerate 30

Hide
Type "unset CLAUDECODE SVELTE_VITALS_AGENT CI"
Enter
Type "alias svelte-vitals='node ../../packages/cli/dist/bin.js'"
Enter
Type "clear"
Enter
Show

Type "svelte-vitals . --reporter console"
Enter
Sleep 2s
Sleep 2s
```

Notes on each non-obvious line:

- `Output ../public/demo.gif` is relative to the directory `vhs` is invoked
  from. Task 3 runs `vhs demo.tape` from inside `docs/demo/`, so this
  resolves to `docs/public/demo.gif`.
- The `Hide` / `Show` block sets up a local alias for the built CLI binary
  _without it appearing in the recording_ — the visible, recorded command
  is the clean `svelte-vitals . --reporter console`, matching what a real
  user would type against a published package, even though it's actually
  invoking the local build. `clear` inside the hidden block wipes the shell
  banner so the very first visible frame is a clean prompt.
- `unset CLAUDECODE SVELTE_VITALS_AGENT CI` clears any agent/CI env vars
  `vhs` itself inherited from whatever shell launched it (e.g. this repo's
  own agent-driven sessions set `CLAUDECODE`). This is required as of
  `packages/cli/src/reporter-resolve.ts`'s `isAgentEnv`/`isCiEnv`, used
  **unconditionally** by `scoreAnimationEnabled` (a fix that landed after
  this plan was first drafted, in response to a PR review comment — see
  `docs/superpowers/plans/2026-07-10-console-reporter-compact-animated.md`).
  Passing `--reporter console` explicitly is no longer enough on its own to
  get the animation inside a detected agent shell; the env vars themselves
  must be gone for that specific subprocess. Baking the `unset` into the
  tape's hidden setup (rather than requiring whoever runs `vhs demo.tape`
  to remember to `env -u` it externally) keeps the recording reproducible
  regardless of the invoking shell's ambient environment.
- `--reporter console` is still passed **explicitly**, not left to
  auto-detection, for a second, independent reason: it also sidesteps
  `resolveReporter`'s own agent-env auto-selection, which would otherwise
  swap in the Markdown `agent` reporter (`isAutoDetectedAgent` only
  returns `false` when an explicit reporter is given — this part is
  unaffected by the `scoreAnimationEnabled` fix above, which is a separate
  gate).
- No `--no-color` / `--no-animation`: `vhs` runs the command in a real pty,
  so `process.stdout.isTTY` is `true` and the pulse animation plays exactly
  as it would for an interactive human user — nothing needs to be forced.
- Two `Sleep 2s` calls, not one `Sleep 4s`: the first covers analysis
  (near-instant on a 5-route fixture) plus the ~1.2s pulse animation
  (`FRAME_COUNT * FRAME_DELAY_MS` in `packages/cli/src/pulse-animation.ts`)
  plus the category score lines that print immediately after; the second is
  the hold so a viewer watching the GIF loop can read the final score
  before it restarts. Keeping them as two lines documents which is which —
  collapse or extend them in Task 3 if the actual recording needs
  retiming.

reaches the Astro build in Task 4).

`docs/public/demo.gif` in an image viewer (or a browser tab) and confirm:

`Health: 95/100` line is readable, the five category score lines
(`SEO Score:`, `Performance Score:`, `Correctness Score:`, `Security
Score:`, `Architecture Score:`) appear right after, and the loop point
(GIF restarting) isn't jarring. If not, adjust `demo.tape`'s `Set
FontSize`/`Set Width`/`Set Height`/`Sleep` values and re-run Step 3.

Use `image: { html: ... }`, not `image: { file: ... }` — `file` (and
`dark`/`light`) route through Astro's `astro:assets` `<Image>` component
(see `Hero.astro`'s `darkImage`/`lightImage` branch), which runs local
images through Sharp for optimization; Sharp only keeps the first frame of
an animated GIF, silently flattening the animation. `html` is a raw-HTML
passthrough (the `rawHtml` branch), the same reasoning `hero.title` already
relies on for the wordmark.
